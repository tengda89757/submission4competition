\begin{abstract}
This report describes a unified RobotAgent for the five JCIIOT 2026 RunningRobot factory-sorting levels and, equally importantly, an auditable chain from the official task definition to the submitted trajectory bytes. The previous package can be reproduced as exactly 65/100 under the task definition at commit \commit: L3 used the obsolete \texttt{input\_6} / left-blue route and L5 released at obsolete \texttt{output\_6}. The corrected system binds execution to the current official routes, synthesizes grasp approach frames online from official object sites, performs clearance-aware base positioning entirely in the editable skill layer, and maintains L5 state continuity across three physical grasp/place cycles. Five packaged trajectories recompute to 10, 15, 20, 25, and 30 points, with no recorded collision flags. We deliberately distinguish this deterministic local rescore from the organizer's final code-audited result. No trajectory JSON, locked task configuration, transport attachment, or official environment file is post-processed by participant code.
\end{abstract}

\section{Method}

\subsection{Exact auxiliary-station resolution}

Auxiliary names contain ordinary station names as substrings: for example, \texttt{output\_1} is contained in \texttt{aux\_output\_1}. The previous substring-first resolver could therefore navigate to the wrong station even when the LLM emitted the correct target. The final resolver first tests an exact known name, then tests embedded names in decreasing length order. This small ordering invariant is essential for both L3 and L5 and requires no task-config change.

\begin{lstlisting}[language=Python,caption={Exact-first station resolution in the editable skill layer.}]
names = scene.all_port_names()
exact = target.strip()
if exact in names:
    return station_goal(exact)
for name in sorted(names, key=len, reverse=True):
    if name in target:
        return station_goal(name)
\end{lstlisting}

\subsection{Hybrid grasp with runtime geometry synthesis}

The official BC checkpoint remains the first attempt in fallback mode. When it fails outside its familiar geometry, a deterministic expert uses the official collector's lift, XY approach, descent, settle, close, and lift primitives. Event recording and official transport attachment remain in the unchanged backend.

The base approach is computed from live model geometry rather than written into the locked task configuration. Let object centre be $c$, and let $s_R,s_L$ be the official right and left grasp sites. The measured outward direction and base pose are

\begin{equation}
u = \frac{(s_R+s_L)/2-c}{\lVert (s_R+s_L)/2-c \rVert},\qquad
b = c + d u,\qquad d=0.941\text{ m}.
\end{equation}

For objects whose natural standing side is blocked, the skill rotates this frame at runtime:

\begin{equation}
u' = R_z(\theta)u,\qquad
p_{R,L}=c+f u'\pm \ell R_z(90^\circ)u',
\end{equation}

where $f=0.315$ m, $\ell=0.11$ m, $\theta=+90^\circ$ for the selected L2/L5 totes, and $\theta=-90^\circ$ for the selected L3 right-side tote. The points $p_R,p_L$ are controller targets for the current grasp call; they do not rewrite XML sites, semantic maps, task configuration, or trajectory data.

\subsection{Clearance-aware staging in the skill layer}

Navigation uses the official occupancy grid and official A* primitives. The editable MoveSkill creates temporary in-memory dilations with margins $0.45$, $0.30$, $0.15$, and $0$ m. Start and goal neighborhoods are restored from the official grid so valid table approaches are not removed. The first feasible margin is selected; the final stage is exactly the unmodified official grid.

For grasp positioning, the robot first drives to a staging point $0.65$ m behind the computed base pose, turns with the official turn controller, and then follows a short straight physical approach. L5 keeps an additional $0.10$ m table clearance. This prevents an extended arm from sweeping through a table during a large turn and preserves the base/object relationship captured by the official backend.

\subsection{L5 transaction-scoped state continuity and placement}

The official grasp helper creates a wrapped environment and synchronizes all material objects back to the navigation environment after a grasp. During a three-object task, that blanket synchronization can overwrite the physical result of earlier placements. The PickUpSkill therefore snapshots only non-target free-joint states before the official grasp call and restores those same non-target states afterward. It does not move the selected target, declare a grasp successful, or write transport attachment state; success and attachment remain controlled by the official grasp/lift pipeline.

Placement is similarly scoped. The three calls use the target centre and lateral offsets of $0$ m, $+0.38$ m, and $-0.38$ m. Only the temporary station centre consumed by the official place controller is changed, and it is restored immediately after each call. Final positions are determined by physics and recorded normally.

\section{Novelty Statement}
\label{sec:novelty}

The innovation claim in this revision is intentionally narrower and more auditable than the earlier draft. We do not claim a new imitation-learning algorithm, a general proof of safety, or state-of-the-art performance beyond this benchmark. The contribution is a set of composable skill-layer mechanisms that bridge an official learned/physics baseline to multi-scene execution while preserving the evaluation boundary.

\begin{enumerate}
\item \textbf{Runtime site-relative grasp-frame synthesis.} Official model sites become measurements rather than files to patch. One geometric formulation produces both natural and rotated controller targets and is exercised in L2, L3, and L5.
\item \textbf{Physically consistent two-stage base positioning.} A temporary clearance ladder, a safe staging pose, an official physical turn, and a straight final approach are combined inside allowed skills. The approach addresses both collision exposure and attachment-frame consistency without writing attachment data.
\item \textbf{Transaction-scoped multi-object continuity.} Non-target state preservation around the official wrapped grasp call prevents later grasps from erasing earlier placements. Three target-table points then convert a repeated single-object primitive into a stable three-object sequence.
\item \textbf{Versioned evidence chain.} One check binds the task commit, accepted candidates, ZIP members, raw/package hashes, and recomputed scores. This exposes stale-task success and trajectory post-processing.
\end{enumerate}

\section{Experimental Protocol}

\subsection{Trajectory selection and scorer}

The canonical set contains one successful simulator trajectory per level. L1, L2, and L4 retain valid earlier trajectories because their routes did not change. L3 and L5 were rerun against the corrected official routes. The strict verifier opens each ZIP, requires exactly \texttt{trajectory.json}, \texttt{score.json}, and \texttt{submission\_manifest.json}, checks the manifest commit, hashes both package and trajectory bytes, and recomputes the score using the pinned task candidates.

The verifier does not run an LLM, MuJoCo, or rendering. It evaluates the recorded state sequence. This is useful for deterministic auditing, but it is not a substitute for the organizer's final source-code review.

\subsection{Integrity controls}

\begin{itemize}
\item Packaged \path{trajectory.json} is a byte-for-byte copy of the raw simulator \path{trajectory_*_OK.json}.
\item The packaging script writes only \texttt{score.json} and \texttt{submission\_manifest.json}; it does not rewrite trajectory frames.
\item No participant skill writes the official transport-attachment structure.
\item Full machine-readable report: \texttt{verification\_report.json} in the final-package directory.
\item The all-in-one archive SHA-256 is
\texttt{a866718e44314ce5}\allowbreak\texttt{ffe7844a3b8a4d8b}\allowbreak

\section{Limitations}

\begin{enumerate}
\item The reported 100/100 is a deterministic rescore of one selected trajectory per level, not a repeated-trial success-rate estimate.
\item The rotated approach constants are validated on the named competition objects and are not claimed to generalize to arbitrary geometry without additional collision perception.
\item Non-target state restoration compensates for the official wrapper's blanket synchronization. A future backend API that synchronizes only the grasped target would remove this skill-level transaction.
\item The task is evaluated in static maps. Dynamic obstacles would require online local replanning.
\item Final acceptance remains subject to organizer code audit; this report documents evidence and boundaries rather than asserting organizer approval in advance.
\end{enumerate}

\section{Conclusion}

The central lesson of this submission is that the 65-point discrepancy was not evidence of trajectory editing; it was the exact consequence of stale official-task routing in L3 and L5. The corrected system reaches a recomputed 100/100 while keeping official core, environment, task, and map files unchanged. Its technical contribution is not an inflated SOTA claim, but an auditable set of skill-layer mechanisms: runtime grasp-frame synthesis, clearance-aware staged base motion, transaction-scoped multi-object continuity, and integrity-bound verification. Each claim in this revision maps to current code or recorded trajectory evidence.
